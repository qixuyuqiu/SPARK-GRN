# SPARK-GRN

SPARK-GRN is a prior-aware framework for ranking directed transcription
factor (TF)-target gene (TG) candidates from single-cell RNA-seq data, with
optional integration of gene-level chromatin accessibility. The regulatory
prior is used as the RNA message-passing graph but does not restrict the
candidate edge space.

This repository accompanies the SPARK-GRN *Bioinformatics* manuscript and
contains the complete model used in the study. 

## Model overview

SPARK-GRN combines four components:

1. a direction-aware dual-branch GATv2 RNA encoder;
2. a variational encoder for ATAC-derived GeneActivity;
3. uncertainty-aware residual RNA-ATAC fusion;
4. a direction-preserving dual-path KAN link scorer.

The same implementation supports RNA-only, paired RNA-ATAC, and unpaired
RNA-ATAC analyses. RNA and ATAC matrices must share an ordered gene space, but
their cell columns do not need to correspond.

## Repository contents

```text
src/spark_grn/                 Model, data loading, training, and inference
configs/beeline/               RNA-only presets used in the manuscript
configs/multiomics/            Paired RNA-ATAC presets
configs/unpaired_multiomics/   Unpaired RNA-ATAC presets
scripts/                       BEELINE, paired, and unpaired benchmark runners
Data/                          Processed matrices and fixed edge splits
outputs/                       Run outputs when present; regenerated by scripts

```

The `Data/` directory contains model-ready derivatives and the exact
cross-validation partitions used by the supplied runners. It does not replace
the original public records. Dataset accessions and citations are reported in
Supplementary Table S11, and preprocessing is described in the Supplementary
Methods.

## System requirements

- Python 3.10-3.12
- PyTorch 2.11.0
- PyTorch Geometric 2.7.0
- NumPy, pandas, SciPy, scikit-learn, and tqdm
- A CUDA-capable GPU is recommended for full benchmark reproduction; CPU
  execution is supported.

The release was tested with Python 3.12.13, PyTorch 2.11.0+cu130, and PyTorch
Geometric 2.7.0. Exact Python package versions are listed in
`requirements.txt`.

## Installation

Clone the repository, create an isolated environment, and install SPARK-GRN:

```bash
git clone https://github.com/qixuyuqiu/SPARK-GRN.git
cd SPARK-GRN

conda create -n spark-grn python=3.12 -y
conda activate spark-grn

python -m pip install --upgrade pip
python -m pip install -e .
```

For GPU execution, install the PyTorch build appropriate for the local CUDA
driver before running `python -m pip install -e .`.

Confirm that the package and command-line entry points are available:

```bash
python -c "import spark_grn; print(spark_grn.__version__)"
spark-grn-train --help
spark-grn-predict --help
```

## Input data

SPARK-GRN requires a gene-by-cell expression matrix and training, validation,
and test edge files. The multimodal model additionally requires a gene-by-cell
GeneActivity matrix.

- `ExpressionData.csv`: genes in rows and RNA cells in columns.
- `GeneScoreData.csv`: genes in rows and ATAC cells in columns.
- `Train_set.csv`, `Validation_set.csv`, and `Test_set.csv`: directed TF-TG
  pairs with binary labels.
- Candidate file for prediction: two columns identifying TF and TG.

Gene identifiers or zero-based gene indices are accepted for edge files. The
training prior is constructed exclusively from positive rows of
`Train_set.csv`. Complete schemas, accepted column names, and directory layouts
are documented in `DATA_FORMAT.md`.

## Train one fold

The command below trains the complete multimodal model on A549 Repeat 1,
Fold 1 and evaluates the checkpoint selected by validation AUPRC on the held-out
test split:

```bash
spark-grn-train \
  --config configs/multiomics/A549.json \
  --expression Data/Multi-omics/dataset/A549/ExpressionData.csv \
  --gene-activity Data/Multi-omics/dataset/A549/GeneScoreData.csv \
  --train Data/Multi-omics/Train_validation_test_repeated/A549/Repeat_01/Fold_1/Train_set.csv \
  --validation Data/Multi-omics/Train_validation_test_repeated/A549/Repeat_01/Fold_1/Validation_set.csv \
  --test Data/Multi-omics/Train_validation_test_repeated/A549/Repeat_01/Fold_1/Test_set.csv \
  --output outputs/A549/Repeat_01/Fold_1 \
  --device cuda:0 \
  --deterministic
```

Use `--device cpu` for CPU execution. For RNA-only training, select a preset
under `configs/beeline/` and omit `--gene-activity`.

Each run writes:

- `best_model.pth`: checkpoint with the highest validation AUPRC;
- `resolved_config.json`: complete configuration used for the run;
- `training_history.json`: epoch-level training history;
- `test_metrics.json`: held-out test metrics; and
- `run_manifest.json`: software, device, seed, and runtime metadata.

## Rank candidate edges

After training, score an ordered list of TF-TG candidates as follows:

```bash
spark-grn-predict \
  --config configs/multiomics/A549.json \
  --checkpoint outputs/A549/Repeat_01/Fold_1/best_model.pth \
  --expression Data/Multi-omics/dataset/A549/ExpressionData.csv \
  --gene-activity Data/Multi-omics/dataset/A549/GeneScoreData.csv \
  --train Data/Multi-omics/Train_validation_test_repeated/A549/Repeat_01/Fold_1/Train_set.csv \
  --validation Data/Multi-omics/Train_validation_test_repeated/A549/Repeat_01/Fold_1/Validation_set.csv \
  --test Data/Multi-omics/Train_validation_test_repeated/A549/Repeat_01/Fold_1/Test_set.csv \
  --candidates candidates.csv \
  --output ranked_candidates.csv \
  --device cuda:0
```

The output contains TF and TG identifiers, their gene indices, and a continuous
regulatory score, sorted from highest to lowest.

## Reproduce manuscript benchmarks

Run the fixed five-fold BEELINE RNA-only benchmark:

```bash
python scripts/run_beeline_5fold.py \
  --repeats 1 \
  --gpu-ids 0 \
  --max-workers 5 \
  --deterministic
```

Run the 10 repeated five-fold paired RNA-ATAC benchmark:

```bash
python scripts/run_paired_multiomics_cv.py \
  --repeats 10 \
  --gpu-ids 0 \
  --max-workers 5 \
  --deterministic
```

Run the 10 repeated five-fold unpaired RNA-ATAC benchmark:

```bash
python scripts/run_unpaired_multiomics_cv.py \
  --repeats 10 \
  --gpu-ids 0 \
  --max-workers 5 \
  --deterministic
```

For CPU-only execution, replace the GPU settings with
`--gpu-ids cpu --max-workers 1`. Batch runners resume successful tasks by
default. Use `--no-resume` to rerun selected tasks and `--dry-run` to inspect a
task plan without training. Dataset, repeat, and fold filters can be supplied
through `--datasets`, `--repeat-ids` or `--repeats`, and `--folds`. Run a script
with `--help` for the complete option list.

## Configuration and optional parameters

All architecture and optimization values used in the manuscript are explicit
in the JSON files under `configs/`. The fields are grouped under `model` and
`training`; accepted ranges are validated by `src/spark_grn/config.py`.

For a single training run, selected values can be overridden without editing a
preset:

```bash
spark-grn-train ... \
  --set training.epochs=50 \
  --set training.batch_size=1024 \
  --set model.fusion_layers=2
```

Overrides use `section.field=value` syntax and JSON-compatible values. The key
optional command-line arguments are:

| Command | Option | Purpose |
|---|---|---|
| training | `--gene-activity PATH` | Required for `BOTH`; omitted for `RNA_ONLY`. |
| training | `--device DEVICE` | Device such as `cuda:0` or `cpu`; auto-selected when omitted. |
| training | `--seed INT` | Replaces the seed stored in the selected preset. |
| training | `--set KEY=VALUE` | Repeated configuration override. |
| training | `--deterministic` | Enables deterministic PyTorch execution where supported. |
| training | `--no-progress` | Suppresses progress output. |
| prediction | `--batch-size INT` | Candidate-scoring batch size; default 4096. |
| batch runners | `--gpu-ids ID ...` | GPU identifiers, or `cpu`. |
| batch runners | `--max-workers INT` | Maximum concurrent fold jobs. |
| batch runners | `--base-seed INT` | Base value used to derive stable model seeds. |
| batch runners | `--no-resume` | Ignores completed-task records and reruns requested tasks. |
| batch runners | `--dry-run` | Prints the planned task identities without training. |

## Reproducibility

- Candidate edges are partitioned before construction of the fold-specific
  training prior.
- Only positive training edges enter the RNA message-passing graph.
- Validation AUPRC controls early stopping and checkpoint selection; test edges
  are not used for tuning.
- Packaged fold directories preserve the fixed edge partitions, and batch
  runners derive stable model seeds from dataset, repeat, and fold identifiers.
- Multimodal inference uses the ATAC posterior mean.
- `--deterministic` requests deterministic algorithms and records the runtime
  environment in `run_manifest.json`.
